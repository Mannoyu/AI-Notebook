# 离线笔记助手：实施任务

状态：实施中。采用规格驱动开发：按[功能规范](spec.md)与[技术设计](plan.md)验证和实现；行为或范围变更先同步规格、验收与本清单。各阶段验证后提交并推送 `origin/dev`。

| 任务 | 交付与完成条件 | 依赖 | 验收追踪 |
| --- | --- | --- | --- |
| T00 | 搭建 Next.js 项目、统一主题、日期索引和编辑页骨架；通过生产构建和类型检查。 | 原型定稿 | 框架门槛，不代替离线验收 |
| T01 | 搭建 Worker，核实上游模型配置；用一篇本地笔记跑通 Ego 下载、试跑与物理断网重开。记录结论和已锁定的模型/依赖版本。 | T00 | AC-04 技术门槛 |
| T02 | 做纯笔记工作区、IndexedDB、自动保存和删除；覆盖排序、持久化与存储错误。 | T01 | AC-01、AC-05 |
| T03 | 做本地文件导入、安全 Markdown 预览和单篇导出；用无分析、当前分析及旧分析样本核对格式。 | T02 | AC-01、AC-02 |
| T04 | 完成模型清单、预检、主动下载、进度、试跑和缺缓存恢复提示；覆盖不可用、跳过及失败分支。 | T01、T02 | AC-03、AC-07 |

| T06 | 用生产构建在用户的 Windows + Ego 执行整套验收，分别验证仅笔记、模型就绪和仅模型缓存缺失三种离线状态。 | T03、T04、T05 | AC-01 至 AC-07 |

**检查方法**：以自动化测试覆盖版本判断、分片预算、Markdown 导出和任务失败等确定性逻辑；使用模拟 Worker 覆盖状态与竞态；真实 Ego 验收必须使用系统断网和浏览器完整重启，不能用模拟 Worker 或在线刷新代替。记录版本、步骤、期望和实测结果。T01 若失败，回到技术设计修订并重测，不把未验证的参数写成既定事实。

**当前进度**：T00 已通过；T01–T05 已实现并在 Ego 验证主要流程。T01 的系统断网与完整重启门槛及 T06 的剩余验收分支未完成。详见[验收记录](acceptance.md)。
